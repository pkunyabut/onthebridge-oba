# OnTheBridge OBA (ฉบับย่อภาษาไทย)

**ระบบเขียนบทความแบบกึ่งอัตโนมัติ ที่มีด่านให้คนตัดสินใจ (Human Gate)**
AI ค้นคว้า สกัดหลักฐาน เขียน ตรวจ และแก้ — แต่ **คนเป็นผู้อ่านและตัดสิน** ระบบ **ไม่เผยแพร่เอง** ไม่ว่ากรณีใด

OBA คือระบบเบื้องหลังของ [OnTheBridge](https://onthebridge.in.th/) สำนักพิมพ์ภาษาไทย (คติ "รู้ให้ลึก เข้าใจก่อนเชื่อ") ใช้งานจริงกับงานเขียนภาษาไทย
**ทุกบทความผ่านการอ่านและอนุมัติโดยคนที่ Human Gate ก่อนโพสต์ ระบบไม่เผยแพร่เอง**
รุ่นสาธารณะนี้เขียนเป็นภาษาอังกฤษเป็นหลัก และเลือก **ภาษาของบทความ** เป็นไทยหรืออังกฤษได้ในทุกงาน
คู่มือฉบับเต็มเป็นภาษาอังกฤษ: [docs/GUIDE.md](docs/GUIDE.md)

## ต่างจาก "ให้ AI เขียนแล้วโพสต์เลย" อย่างไร

- ทุกข้อเท็จจริงต้องมี **แหล่งที่ระบบเปิดอ่านจริง** และ **ข้อความอ้างอิงที่โค้ดตรวจเทียบกับหน้าเว็บจริง** — ตรวจไม่ผ่านก็ถูกกันออกจากบทความ
- ไม่มี "คะแนนคุณภาพ" ที่วัดไม่ได้ — มีแต่รายการปัญหาพร้อมประโยคที่ผิดและวิธีแก้
- การอนุมัติผูกกับ **ค่า SHA-256 ของไฟล์ที่คนอ่าน** ถ้าไฟล์ถูกแก้ทีหลัง การอนุมัติใช้ไม่ได้
- กติกาบรรณาธิการเป็น **ไฟล์ธรรมดาในโฟลเดอร์ `rules/`** ที่ผู้ใช้เป็นเจ้าของและแก้เองได้ (ไฟล์ที่ให้มาเป็นแค่ตัวอย่าง)
- เชื่อมกับ Claude ผ่าน MCP เพื่อ "ตรวจครั้งสุดท้าย" ได้ โดยไม่มีเครื่องมือเผยแพร่หรืออนุมัติ ([docs/MCP.md](docs/MCP.md))

## เริ่มใช้

ต้องมี Node.js 22 ขึ้นไป และ API key ของผู้ให้บริการ AI อย่างน้อยหนึ่งราย (DeepSeek เป็นค่าเริ่มต้น)

```bash
git clone <ที่อยู่รีโพนี้>
cd <โฟลเดอร์>
npm install
cp .env.example .env     # Windows: copy .env.example .env  แล้วใส่ key ในไฟล์ .env
npm start
```

เปิด **http://127.0.0.1:8080** ใส่หัวข้อ เลือก "ภาษาของบทความ" แล้วกด **Start the article**
(Windows ดับเบิลคลิก `start.bat` ได้) แนะนำให้ใส่ key ค้นเว็บ (Tavily, Serper หรือ Brave) ด้วย

## ช่องทางที่ทดสอบจริง

บทความจากระบบนี้ **ทดสอบโดยโพสต์ขึ้น Blockdit** ซึ่งเป็นโซเชียลมีเดียเฉพาะประเทศไทย (คนโพสต์เองหลังผ่านด่านอนุมัติ)
บทความที่ได้ผู้ใช้นำไปปรับใช้กับ **Facebook, X, LinkedIn หรือที่อื่น** ได้ — ระบบมีตัวร่างแคปชันให้ แต่ **ยังไม่ได้ทดสอบกับแพลตฟอร์มจริง**
และต้องคัดลอกไปโพสต์เองเสมอ

## เลือกโมเดล AI

**คุณภาพของบทความขึ้นกับโมเดลที่เลือก** ด่านตรวจของระบบเหมือนกันทุกโมเดล (ข้อความอ้างอิงต้องเจอในแหล่งจริง ฯลฯ)
แต่ความลื่นไหล ความลึก และการทำตามกติกายาวๆ มาจากโมเดล โมเดลอ่อนมักไม่ทำให้ข้อเท็จจริงผิดหลุดไป แต่จะได้บทความที่อ่อนและต้องแก้หลายรอบ

ระบบทดสอบกับ **DeepSeek** และ **Claude**: DeepSeek Flash ผ่านมาตรฐานของเราทั้งงาน (ฐานที่ตรวจสอบแล้วและราคาไม่แพง) ·
Claude Haiku เขียนจบแต่ต่ำกว่ามาตรฐาน · Claude Sonnet/Opus ต่อใช้งานได้แล้วแต่ **ยังไม่เคยรันทั้งงาน**
ถ้างบไม่ตึง **แนะนำลอง Claude รุ่นใหญ่ (Sonnet/Opus)** เพราะโมเดลใหญ่โดยทั่วไปเขียนดีกว่า — เป็นความคาดหวัง ไม่ใช่ผลที่เราวัดได้
วิธีตัดสินที่เป็นธรรม: รันหัวข้อเดียวกันกับสองโมเดลแล้วเทียบจำนวนรอบที่ต้องแก้และข้อเท็จจริงที่ผ่าน

## ผู้ใช้ต้องพิจารณาบทความทุกเรื่องเอง

ในการทดสอบจริงที่ไม่มี key ค้นเว็บ (ได้แต่ Wikipedia) ข้อเท็จจริงที่ตรวจได้ถูกต้องทุกข้อ และระบบเตือนว่าฐานหลักฐานบางแล้ว แต่บทความ
ยังเขียนซ้ำเพื่อให้ได้ความยาว และมีข้อความเดาที่ฟังดูสมเหตุสมผลแต่ไม่มีแหล่งรองรับ (เช่น "ยังไม่ได้ประกาศ...") ซึ่งด่านตรวจจับไม่ได้ ·
ระบบ **ไม่รู้วันที่ปัจจุบัน** จึงเขียนเหตุการณ์ที่จบแล้วเป็นอนาคตได้ · ควรถือว่า **key ค้นเว็บจำเป็น** (Tavily มีแพ็กฟรี)

## ข้อจำกัดที่ต้องรู้

- "ผ่านการตรวจภายใน" **ไม่ได้รับรองว่าข้อเท็จจริงถูกต้องทั้งหมด** — การตรวจโดย AI ไม่ใช่การตรวจโดยผู้เชี่ยวชาญ จึงต้องมีคนอ่านก่อนเสมอ
- ตารางตรวจข้อเท็จจริงรับรองแค่ว่า "ข้อความตรงกับแหล่งที่อ้าง" ไม่ได้รับรองว่าแหล่งนั้นถูกต้อง
- โมเดลเล็ก/ถูก (เช่น Claude Haiku) เขียนจบงานได้ แต่คุณภาพต่ำกว่ามาตรฐานของโมเดลใหญ่ในการทดสอบของเรา
- ระบบเป็นเครื่องมือ **ใช้คนเดียวในเครื่องตัวเอง ไม่มีระบบล็อกอิน** — ห้ามเปิดให้เข้าถึงจากเครือข่าย (ดู [SECURITY.md](SECURITY.md))
- โมดูลสร้างสคริปต์ Reels ภาษาไทย ยังไม่รวมในรุ่นนี้
