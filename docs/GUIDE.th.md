## 1. สิ่งที่ต้องมี

| ต้องมี | หมายเหตุ |
|---|---|
| คอมพิวเตอร์ที่ติดตั้ง **Node.js 22 ขึ้นไป** | ตรวจด้วย `node --version` ใช้ได้ทั้ง Windows, macOS, Linux ดาวน์โหลดที่ <https://nodejs.org> |
| **API key ของผู้ให้บริการ AI** | อย่างน้อยหนึ่งราย: DeepSeek (ค่าเริ่มต้น), Anthropic, OpenAI, Google Gemini, OpenRouter คุณจ่ายเงินให้ผู้ให้บริการโดยตรง |
| **API key ค้นเว็บ** *(ถือว่าจำเป็น)* | Tavily, Serper หรือ Brave ถ้าไม่มี ระบบจะใช้ Wikipedia และ DuckDuckGo แบบฟรี แต่ DuckDuckGo ไม่ส่งผลลัพธ์ให้โปรแกรม จึงได้ **เฉพาะหน้า Wikipedia** ซึ่งมักมีหน้าที่เกี่ยวข้องจริงเพียงหน้าเดียว (ดู[ภาคผนวก ก](#s19)) Tavily มีแพ็กฟรี |
| เบราว์เซอร์ทั่วไป | หน้าใช้งานเป็นเว็บในเครื่อง |

ไม่ต้องมีฐานข้อมูล ไม่ต้องสมัครบริการของโปรเจกต์นี้ และไม่ต้องมีขั้นตอน build

<a id="s2"></a>
## 2. ติดตั้ง

```bash
git clone <ที่อยู่รีโพนี้>
cd <โฟลเดอร์>
npm install
```

`npm install` ดาวน์โหลดแพ็กเกจไม่กี่ตัว (MCP SDK, `exceljs`, `mammoth`, `pdfjs-dist`, `zod`) ทดสอบว่าทุกอย่างพร้อมโดยไม่เสียเงิน:

```bash
npm test
```

ทุกเทสต์ควรผ่าน เทสต์ไม่ใช้อินเทอร์เน็ตและไม่ใช้ key

<a id="s3"></a>
## 3. ตั้งค่า key (`.env`)

คัดลอกไฟล์ตัวอย่างแล้วแก้:

```bash
cp .env.example .env          # Windows: copy .env.example .env
```

`.env` **ไม่ถูก git เก็บ** จึงไม่ขึ้น GitHub ใส่หนึ่ง key ต่อหนึ่งบรรทัด ไม่ต้องใส่เครื่องหมายคำพูด:

| ตัวแปร | ใช้ทำอะไร |
|---|---|
| `DEEPSEEK_API_KEY` | DeepSeek (ค่าเริ่มต้น) |
| `ANTHROPIC_API_KEY` | โมเดล Claude |
| `OPENAI_API_KEY` | โมเดล OpenAI |
| `GEMINI_API_KEY` | Google Gemini |
| `OPENROUTER_API_KEY` | OpenRouter |
| `TAVILY_API_KEY` | ค้นเว็บ + ดึงหน้าที่บล็อกการเปิดตรงๆ |
| `SERPER_API_KEY` | ผลค้นหาแบบ Google (และแท็บข่าวสำหรับ News analysis) |
| `BRAVE_API_KEY` | Brave Search |
| `GOOGLE_FACTCHECK_API_KEY` | *(ไม่บังคับ)* ใช้กับ **Deep check** |
| `DEEPSEEK_MODEL` | *(ไม่บังคับ)* กำหนดชื่อโมเดล DeepSeek เอง |
| `PORT` | *(ไม่บังคับ)* ค่าเริ่มต้น `8080` |
| `PUBLICATION_NAME`, `SITE_URL` | *(ไม่บังคับ)* ใช้ในร่างจดหมายข่าว/แคปชัน/สคริปต์วิดีโอ |
| `TARGET_ARTICLES` | *(ไม่บังคับ)* เป้าหมายจำนวนบทความที่แถบความคืบหน้าแสดง |

พิมพ์ key ในหน้าเว็บสำหรับงานเดียวได้ (การ์ด **AI provider**) key จะถูกส่งไปที่เซิร์ฟเวอร์ในเครื่องเท่านั้น เก็บในหน่วยความจำระหว่างงานรัน
และ **ไม่เขียนลงดิสก์หรือเบราว์เซอร์** แต่การใส่ใน `.env` เป็นนิสัยที่ดีกว่า

> **ห้าม** วาง key ลงใน issue, แชท, ภาพหน้าจอ หรือ commit ถ้าพลาด ให้ revoke key ที่ผู้ให้บริการทันที แล้วสร้างใหม่

<a id="s4"></a>
## 4. เริ่มและหยุดระบบ

```bash
npm start
```

จะเห็นข้อความ `OnTheBridge OBA running at http://127.0.0.1:8080` เปิดที่อยู่นั้นในเบราว์เซอร์
บน Windows ดับเบิลคลิก `start.bat` แทนได้ หยุดด้วย `Ctrl+C` (หรือปิดหน้าต่าง)

ถ้าพอร์ต 8080 ถูกใช้อยู่ ระบบลอง 8081, 8082… และบอกว่าใช้พอร์ตไหน หรือตั้ง `PORT` ใน `.env`

> **ข้อควรระวัง:** ถ้ามี OBA ตัวอื่นรันอยู่ที่ 8080 (เช่นรุ่นเก่า) หน้าที่เปิดอาจเป็นตัวนั้น ดูข้อความใน Terminal ว่าตัวใหม่ใช้พอร์ตอะไร

เซิร์ฟเวอร์รับเฉพาะ **127.0.0.1** อุปกรณ์อื่นในเครือข่ายเข้าไม่ได้ ควรคงไว้แบบนี้ (ดู [SECURITY.md](../SECURITY.md))

## 5. บทความแรกของคุณ

เปิดแท็บ **Create article** แล้วกรอก:

| ช่อง | ต้องทำอะไร |
|---|---|
| **Topic** *(จำเป็น)* | หัวข้อหรือคำถามที่เจาะจง ยิ่งเฉพาะ ยิ่งได้แหล่งดี เช่น *"ทำไม Amazon ถึงบล็อก shopping agent"* ดีกว่า *"AI กับการช้อปปิ้ง"* ระบบรักษาความหมายที่คุณให้ ไม่ขยายหัวข้อ ไม่เปลี่ยนคำถามเป็นข้อสรุป |
| **Audience** | กลุ่มผู้อ่าน ใช้ในพรอมต์การเขียน |
| **Article language** | อังกฤษหรือไทย กำหนดภาษาที่เขียน ความยาวเป้าหมาย และคำคงที่ที่ระบบเติมเอง (เช่นท้ายบทความ) |
| **Article format (Template)** | เลือก *Let the AI choose* ได้ตอนเริ่ม ดูตารางด้านล่าง |
| **Content Pillar** | ป้ายหมวดเนื้อหาที่กำหนดแนวการเขียน (ดู `rules/`) ปล่อยให้ AI เลือก หรือเลือกเอง |
| **Extra guidance** | สิ่งที่ผู้เขียนต้องทำตาม **สำหรับ Opinion ต้องเขียนจุดยืนของคุณที่นี่** ระบบจะไม่แต่งจุดยืนให้ |
| **External links** | URL ที่ต้องการให้อ่าน ระบบเปิดอ่านก่อนเสมอ และไม่ถูกตัดทิ้งว่า "ไม่เกี่ยวข้อง" |
| **Interview / original text** | วางบทถอดเทปที่อ่านทวนแล้ว เป็นแหล่งหลักฐาน และตรวจคำพูดกับข้อความนี้ตรงๆ |
| **AI provider / Model / API key / Search key** | ดู[หัวข้อ 14](#s14) ปุ่ม **Test the connection** ตรวจ key ด้วยคำขอเล็กๆ |

**เทมเพลต**

| เทมเพลต | ใช้กับ | ต้องมี |
|---|---|---|
| Reflective | ชีวิต ปรัชญา ความหมาย: บทความสะท้อนคิด | ถ้าไม่มีเรื่องจริง ระบบจะพิจารณาจากหลักฐานแทนการแต่งเรื่อง |
| Explainer / How-to | อธิบายแนวคิดหรือขั้นตอนที่ตรวจแล้ว | ระบบไม่แต่งขั้นตอนขึ้นมา |
| Opinion / Column | แสดงจุดยืน | **จุดยืนของคุณในช่อง guidance** ไม่เช่นนั้นระบบจะใช้ Reflective แทน |
| News analysis | เหตุการณ์จริงที่มีหลายฝ่าย เล่าจากแหล่งที่เผยแพร่แล้ว | ใช้การค้นข่าวเมื่อมี key Serper |
| Feature / Narrative | เรื่องของคน สถานที่ คำพูดจริง | ข้อมูลจริงรองรับทุกตัวละครและคำพูด ถ้ามีบทสัมภาษณ์ให้วางไว้ |

**วิธีให้ได้ผลดี (อ่านครั้งเดียว)**

1. **มี key ค้นเว็บ** บทความดีได้เท่าหน้าที่ระบบอ่านได้เท่านั้น
2. **เลือกหัวข้อที่มีแหล่งจริงสาธารณะหลายแหล่ง** เช่นเหตุการณ์ที่มีเอกสารทางการและข่าวหลายสำนัก งานวิจัย นโยบาย หัวข้อที่มีแหล่งเดียวได้บทความบาง
3. **ให้ลิงก์ที่ดี** วางหน้าทางการ (แถลงข่าว คำพิพากษา รายงาน) ในช่อง External links ระบบอ่านก่อนเสมอ ถ้ามีบทสัมภาษณ์ ให้วางบทถอดเทป
4. **บอกสิ่งที่ต้องการในช่อง guidance** รวมมุมที่อยากเล่าและสิ่งที่ต้องหลีกเลี่ยง
5. **จับคู่หัวข้อกับเทมเพลต** News analysis ต้องมีเหตุการณ์จริง Feature/Narrative ต้องมีคนจริงและคำพูดจริง Opinion ต้องมีจุดยืนของคุณ
6. **ใช้โมเดลที่เก่งพอ** ([หัวข้อ 14](#s14)) และเตรียมอ่านกับตัดสินใจเอง — ระบบเตรียม "ฉบับร่างให้คนตรวจ" ไม่ใช่บทความสำเร็จรูป
7. **ระวังวันที่** ระบบไม่รู้ว่าวันนี้วันที่เท่าไร และแหล่งหลายแห่งไม่ระบุวันที่ สำหรับเรื่องที่ไวต่อเวลา (กำลังจะเกิด เพิ่งเกิด หรือเปลี่ยนไปแล้ว) **ตรวจกาลและสถานะเอง**

กด **Start the article** จะมีบรรทัดสถานะแสดงรหัสงาน งานมักใช้เวลาหลายนาทีขึ้นกับโมเดลและจำนวนหน้าที่ต้องดึง ออกจากหน้าได้ งานยังรันต่อที่เซิร์ฟเวอร์
เปิดแท็บ **All jobs** เพื่อดูทุกงานและสถานะ

<a id="s6"></a>
## 6. ระบบทำอะไรระหว่างรัน

เปิดงานเมื่อไรก็ได้เพื่อดู 8 ขั้นตอนที่ค่อยๆ เป็นสีเขียว

| ขั้น | ทำอะไร | ถ้าผิดพลาด |
|---|---|---|
| **brief** | เลือกเทมเพลตและ pillar (ถ้าคุณไม่ได้เลือก) วางคำค้น 3–4 ข้อ และเลือก "คำที่หน้าดีต้องมี" (relevance terms) | — |
| **research** | ค้นหา แล้ว **เปิดหน้าจริง** (HTML และ PDF) ข้ามโซเชียลและวิดีโอ ตัดหน้าที่ไม่มีคำที่ต้องมี และลองดึงหน้าที่บล็อกผ่าน Tavily Extract ถ้ามี key | *"Research found no readable sources"* — ตรวจ key ค้นเว็บและหัวข้อ |
| **evidence** | AI สกัดข้อเท็จจริงสูงสุด 25 ข้อพร้อมคำอ้างอิง **โค้ดตรวจคำอ้างอิงทุกข้อกับข้อความของหน้าจริง** ข้อที่ไม่ผ่านเป็น `needs_verification` และถูกกันออก | *"no fact passed the check"* → งานหยุด **ก่อนเขียน** เพื่อไม่ให้มีบทความที่ไร้หลักฐาน |
| **outline** | จัดข้อเท็จจริงที่ตรวจผ่านลงช่อง (slot) ทั้งสี่ช่อง ช่องละข้อเท็จจริงอยู่ได้ที่เดียว และตั้งชื่อหัวข้อ | — |
| **write** | เขียนทีละช่อง แต่ละช่องมีข้อเท็จจริงและเป้าความยาวของตัวเอง และเห็นช่องที่เขียนไปแล้ว ช่องที่ยาวเกินจะถูกขอให้กระชับหนึ่งครั้ง | — |
| **review** | ตรวจด้วยโค้ด + ผู้ตรวจ AI ข้อที่ต้องแก้กลับไปขั้น *write* เพื่อแก้ **ทีละประโยค** สูงสุด **3 รอบ** | หลัง 3 รอบ รายการที่เหลือแสดงให้คุณดู |
| **channels** | สร้างข้อความที่พร้อมให้คนอ่าน: หัวข้อของคุณ เลขแหล่ง `[1][2]` ท้ายบทความบอกวันที่เข้าถึง รายการ Sources และ *แผนภาพ* (ไม่ใส่ลิงก์ภาพ — ดู[หัวข้อ 11](#s11)) | — |
| **final** | ตรวจครั้งสุดท้ายที่ **รายงานอย่างเดียว ไม่เคยอนุมัติ** | — |

จากนั้นงานหยุดรอ **คุณ**

## 7. อ่านผลลัพธ์ และสิ่งที่ด่านตรวจจับได้/พลาดได้

เปิดงานจาก **All jobs** จากบนลงล่าง:

**สถานะ**

| สถานะ | ความหมาย |
|---|---|
| `ready_for_review` | ผ่านการตรวจภายใน รอคุณ ไม่ใช่การอนุมัติ |
| `needs_revision` | ยังมีข้อที่ต้องแก้หลังรอบภายใน คุณอ่านได้ ส่งกลับ หรืออนุมัติหลังยืนยันว่ารับทราบ |
| `approved` | คุณอนุมัติไฟล์ฉบับนี้แล้ว |
| `cancelled` | คุณยกเลิกแล้ว |
| `error` | มีขั้นตอนล้มเหลว ข้อผิดพลาดแสดงที่งาน |

**การ์ดสถานะ (สีเขียวหรือเหลือง)** แสดง:

- **Blockers** — ข้อที่ต้องแก้ แต่ละข้อมี *ชนิด* (เช่น `unsupported`, `misattributed`, `duplicate_paragraph`), **ประโยคตรงตัว**, เหตุผล และวิธีแก้ที่แนะนำ
- **Notes** — สิ่งที่ไม่บล็อกแต่ควรรู้: จำนวนคำนอกช่วง ข้อเท็จจริงที่ถูกกันออก แหล่งที่เปิดไม่ได้ ย่อหน้าที่ระบบตัดออกเอง
- **Evidence base: thin / enough** — คำนวณจากข้อเท็จจริงที่ตรวจผ่านและองค์กรต้นทาง เตือนเมื่อเช่น 90% ของข้อเท็จจริงมาจากหน่วยงานเดียว การแก้ข้อความสร้างหลักฐานไม่ได้ ถ้าฐานบาง ให้เพิ่มลิงก์แหล่งอิสระ หรือยอมรับบทความที่สั้นกว่า
- **ข้อสังเกตด้านสำนวน/ความซ้ำ** — เป็นคำแนะนำ ไม่บล็อก

**ชนิดปัญหาที่จะพบ**

| ชนิด | ความหมาย |
|---|---|
| `unsupported` | ข้อเท็จจริง ตัวเลข วันที่ ชื่อ หรือเหตุการณ์ที่ไม่อยู่ในข้อเท็จจริงที่ตรวจแล้วหรือแหล่ง |
| `embellished` | เติมรายละเอียดเกินต้นฉบับ หรือทำให้ความหมายแรงขึ้น |
| `misattributed` | อ้างคำพูดหรือความเห็นผิดคนหรือผิดสำนัก (โค้ดตรวจซ้ำกับแหล่ง) |
| `incomplete` | เรื่องหลายฝ่ายที่เล่าด้านเดียว |
| `fabricated_experience` | ประสบการณ์หรือฉากที่เขียนเหมือนจริงแต่ไม่มีหลักฐาน |
| `repetition` / `duplicate_paragraph` | เล่าซ้ำเพื่อเพิ่มความยาว |
| `hypothetical_opening` | เปิดเรื่องด้วย "ลองจินตนาการ…" หรือ "คุณเพิ่ง…" แทนเหตุการณ์จริง |
| `cjk` | พบอักษรจีน/ญี่ปุ่น/เกาหลีในข้อความที่ควรเป็นอังกฤษหรือไทย |
| `leaked_json` | ข้อความดิบของโมเดลหลุดมาในบทความ |
| `word_count` | อยู่นอกช่วงเป้า (ไม่บล็อก) |

ระบบ **ไม่ให้คะแนนตัวเลข** โดยตั้งใจ เพราะตัวเลขสื่อถึงความแม่นยำที่วิธีนี้ไม่มี

ใต้การ์ดคือบทความตามไฟล์ `blockdit.md` เป๊ะๆ ซึ่งเป็นไฟล์ที่การอนุมัติของคุณจะผูกไว้

### ด่านตรวจจับอะไรได้ และพลาดอะไรได้

นี่คือสิ่งสำคัญที่สุดที่ต้องเข้าใจเกี่ยวกับ OBA **"พร้อมให้คนตรวจ" ไม่ได้แปลว่า "ถูกต้อง"**

| ระบบ **จับได้** | ระบบ **พลาดได้** — คุณต้องดูเอง |
|---|---|
| ตัวเลข ชื่อ วันที่ หรือคำพูดที่ **ไม่อยู่ในหน้าที่อ้าง** (ตรวจด้วยโค้ด) | ประโยคที่ **ไม่มีตัวเลข ชื่อ หรือคำพูด** แต่บอกสิ่งที่แหล่งไม่เคยพูด เช่น *"เจ้าภาพยังไม่ประกาศแผน"* หรือ *"วาระยังไม่ได้ยืนยัน"* การเดาที่ฟังดูสมเหตุสมผลผ่านได้ |
| ข้อเท็จจริงที่หาข้อความอ้างอิงในหน้าไม่เจอ → ถูกกันออก | **ใครเป็นคนพูด** บทความอาจเรียกแหล่งว่า *"คำอธิบายของสถาบันเอง"* ทั้งที่หน้านั้นคือสรุปใน Wikipedia ให้เทียบถ้อยคำกับรายการ Sources |
| **ย่อหน้า** ซ้ำ, หัวเรื่องที่เปิดด้วย "ลองจินตนาการ…", JSON ดิบ, อักษร CJK | **ประโยคหรือความคิดที่ซ้ำ** ในหรือข้ามช่อง การซ้ำรายงานเป็น *ข้อสังเกต* ไม่ใช่ blocker ข้อเท็จจริงเดียวอาจโผล่สามถึงสี่ครั้ง |
| ฐานหลักฐานบาง (องค์กรเดียว ข้อเท็จจริงน้อย) → หมายเหตุบนการ์ด | **แหล่งที่ใช้ถูกเรื่องหรือไม่** ถ้าการค้นพาหน้าไม่เกี่ยวข้องเข้ามา ข้อเท็จจริงอาจ "ตรวจผ่าน" กับหน้านั้นทั้งหมด |
| เนื้อหาที่เพิ่มโดยไม่มีแหล่ง (ในการตรวจสุดท้ายผ่าน MCP) | **เวลา** ระบบไม่รู้วันที่ปัจจุบัน เหตุการณ์ที่จบแล้วอาจถูกเขียนเป็นอนาคต และกลับกัน |
| — | **ข้อเท็จจริงที่ล้าสมัยหรือเปลี่ยน** *ตรวจแหล่งซ้ำ* ([หัวข้อ 9](#s9)) บอกแค่ว่าหน้าเปลี่ยนไหม ไม่ได้บอกว่าถูกหรือไม่ |
| — | **ความเป็นธรรมและน้ำหนัก** การให้น้ำหนักแต่ละฝ่ายเหมาะสมหรือไม่ เป็นดุลยพินิจของคน |

ด่านตรวจผูกข้อความกับแหล่ง แต่ไม่ตัดสินแหล่ง การวางกรอบ หรือสามัญสำนึก

### รายการตรวจก่อนกดอนุมัติ

ใช้เวลาสองนาที ถ้าข้อไหนตอบว่า "ไม่" ให้ **ส่งกลับ** พร้อมคำสั่งเฉพาะเจาะจง หรือยกเลิก

1. **แหล่งอ้างอิง** เปิดรายการ Sources เป็นแหล่งที่คุณจะอ้างเองไหม มีองค์กรอิสระมากกว่าหนึ่งแห่งไหม (บรรทัด *Evidence base* ในการ์ดบอกไว้ ถ้า *thin* ให้ระแวงบทความ)
2. **ทุกประโยคที่บอกสิ่งใหม่** มีเครื่องหมาย `[n]` ไหม ระวังประโยคที่พูดถึง *สิ่งที่ยังไม่เกิด*, *สิ่งที่คาดว่าจะเกิด*, *ความเห็นของใคร* หรือ *เหตุผลว่าทำไม* เพราะนี่คือที่ซ่อนของการเดาที่ไม่มีแหล่ง
3. **ใครพูดอะไร** หาทุกที่ที่เขียนว่า "ตามที่…", "กล่าวว่า…", "คำอธิบายของสถาบัน" ระบุแหล่งถูกต้องไหม
4. **วันที่และกาล** ลำดับเวลาในบทความจริง **ณ วันนี้** ไหม มีเหตุการณ์ที่เขียนว่ากำลังจะเกิดทั้งที่เกิดไปแล้วไหม
5. **การซ้ำ** ข้อเท็จจริงเดียวโผล่หลายครั้งไหม ถ้าบทความรู้สึกถูกยืด แสดงว่าหลักฐานน่าจะน้อยเกินกว่าความยาวเป้า — ขอให้เขียนสั้นลงหรือเพิ่มแหล่ง
6. **หัวเรื่องและบทปิด** ตรงกับสิ่งที่เนื้อหาพิสูจน์จริงไหม
7. **รัน Fact check** ([หัวข้อ 9](#s9)) แล้วเปิดทุกข้อใน *Check yourself* และ *High-risk*
8. **ตัวเลขและชื่อที่คุณจะนำไปพูดต่อสาธารณะ** เปิดแหล่งแล้วอ่านบรรทัดนั้นเอง
9. **คุณจะใส่ชื่อตัวเองไว้ในบทความนี้ไหม** (คลังน้ำเสียงให้เจ้าของงานตอบข้อนี้ที่ Human Gate AI ห้ามตอบแทน)

การอนุมัติหมายความว่า *คุณ* ยืนยันไฟล์นี้ นั่นคือจุดประสงค์ของด่าน

<a id="s8"></a>
## 8. Human Gate: อนุมัติ ส่งกลับ ยกเลิก

แผงตัดสินอยู่เหนือบทความ **อ่านทั้งบทความก่อน**

- **ชื่อของคุณ** — บันทึกพร้อมคำตัดสิน
- **Note** — บังคับเมื่อส่งกลับ (ระบุให้ชัดว่าต้องแก้อะไร เช่น *"ตัดย่อหน้าเรื่องหุ้นออก"*)

| ปุ่ม | เกิดอะไรขึ้น |
|---|---|
| ✅ **Approve** | บันทึกชื่อ เวลา หมายเหตุ และ **ค่า SHA-256 ของไฟล์ที่คุณเห็น** ถ้ายังมี blocker ต้องยืนยันว่าอ่านแล้ว |
| ✏️ **Send back for edits** | คำสั่งของคุณกับ blocker ที่เหลือไปถึงผู้เขียน ซึ่งแก้ **ทีละประโยค** ในฉบับร่างเดิมแล้วตรวจซ้ำ ได้เวอร์ชันใหม่ |
| ✖ **Cancel** | ทำเครื่องหมายว่างานถูกยกเลิก |

ค่า hash ผูกอะไร: ถ้าไฟล์ในดิสก์ต่างจากที่อนุมัติ — แม้ตัวอักษรเดียว แม้คุณเองแก้ในโปรแกรมแก้ไข —
การอนุมัติจะแสดงว่า **ใช้ไม่ได้** และไฟล์นั้นอนุมัติหรือส่งกลับไม่ได้จนกว่าจะยกเลิกหรือสร้างใหม่ หน้าเว็บยังปฏิเสธคำตัดสินที่ทำบนสำเนาเก่า
("the version you opened is not the latest — reload")

งานที่อนุมัติแล้วยังส่งกลับหรือยกเลิกได้ แต่อนุมัติซ้ำไม่ได้

**ทำไมปุ่มใช้ได้เฉพาะจากหน้าเว็บ:** ระบบรับคำตัดสินเฉพาะคำขอที่มี header `Origin`/`Sec-Fetch-Site` ของเบราว์เซอร์เอง
สคริปต์ คำสั่ง `curl` หรือเครื่องมือ AI จึงอนุมัติโดยพลาดไม่ได้ นี่กัน *ความพลาด* ไม่ได้กันผู้โจมตีที่ตั้งใจและอยู่ในเครื่องเดียวกัน
— OBA เป็นเครื่องมือผู้ใช้คนเดียว ไม่ใช่ระบบยืนยันตัวตน

<a id="s9"></a>
## 9. ตรวจข้อเท็จจริงก่อนโพสต์

สำหรับงานสถานะ `ready_for_review`, `needs_revision` และ `approved` แผงมี **Fact check before posting**:

- **Check the approved version** — เทียบ **ตัวเลข ชื่อเฉพาะ และข้อความในเครื่องหมายคำพูด** ทุกตัวกับแหล่งที่ประโยคนั้นอ้าง (`[n]`) ทำด้วยโค้ด ไม่ใช้ AI แสดงรายการ *Check yourself* และ *High-risk items* (ข้อกล่าวหา เรื่องกฎหมาย คำพูด ข้อเท็จจริงที่มีแหล่งเดียว) ก่อน และเขียน `fact_check.md` ลงโฟลเดอร์งาน
- **Check the pasted text** — ถ้าคุณแก้บทความหลังอนุมัติ วางฉบับที่จะโพสต์จริง ต้องมีเลข `[1] [2]` เหมือนเดิม
- **Deep check** — ค้นหา **แหล่งอิสระที่สอง** สำหรับข้อเท็จจริงเสี่ยงสูงที่มีแหล่งเดียว และถาม Google Fact Check Tools เรื่องข้อกล่าวหาและคำพูด มีค่าค้นหาเล็กน้อย ต้องมี key Tavily/Serper (และ `GOOGLE_FACTCHECK_API_KEY` ถ้ามี) การไม่พบผล **ไม่ได้แปลว่า** ข้อกล่าวอ้างนั้นจริง
- **Re-check the sources** *(งานที่อนุมัติแล้ว)* — เปิดทุกลิงก์อ้างอิงอีกครั้งแล้วเทียบกับสำเนาตอนเขียน เตือนเมื่อหน้าหาย เปลี่ยนมาก หรือข้อความที่ใช้ยืนยันหายไป ใช้ทั้งก่อนและหลังเผยแพร่

สิ่งที่บอกได้และบอกไม่ได้: รับรองว่า *ข้อความตรงกับแหล่งที่อ้าง* แต่ **ไม่รับรองว่าแหล่งนั้นถูกต้อง** ตัวเลขที่เขียนเป็นคำในบทความ และหน่วยเงิน ไม่ถูกตรวจ

## 10. เวอร์ชันและสิ่งที่เปลี่ยน

ทุกเวอร์ชันที่ส่งให้ตรวจถูกเก็บไว้ที่ `versions/v<N>/` ในโฟลเดอร์งาน ไม่เขียนทับ ไม่ลบ
กด **List / compare what changed** เพื่อดูแต่ละเวอร์ชันพร้อมจำนวนคำและคำตัดสิน และเทียบเวอร์ชันเก่ากับปัจจุบันทีละย่อหน้า (แดง = ถูกลบหรือเปลี่ยนจาก, เขียว = เพิ่มหรือเปลี่ยนเป็น)

## 11. โพสต์บทความ

OBA **ไม่โพสต์เอง** หลังอนุมัติ:

1. **Blockdit / ช่องทางบทความยาว** — คัดลอกบทความ (📋 *Copy* หรือ *Download .md*) แล้วโพสต์เอง ข้อความมีเลข `[1][2]` และรายการ Sources
2. **ภาพ** — OBA เขียน **แผนภาพ** (`image_plan.md` และกล่อง *Image prompts*) แต่ไม่สร้างภาพ และ **ไม่ใส่ลิงก์ภาพ** ในบทความ จึงไม่เคยอ้างภาพที่ไม่มีจริง เมื่อคุณเพิ่มภาพ: ใช้เฉพาะภาพที่มีสิทธิ์ ใส่เครดิต และระบุว่าเป็นภาพ AI ถ้าเป็นภาพ AI ภาพจำลองไม่ใช่หลักฐานของเหตุการณ์
3. **เว็บไซต์** — แผง *Website category code* แนะนำรหัสจาก pillar (เป็นตารางตัวอย่างใน `src/webCategory.mjs` ให้แก้ให้ตรงกับเว็บของคุณ) ส่วน **Plain HTML page** ใน *Drafts for other channels* ให้ HTML ที่ escape แล้ว
4. **Facebook, X, LinkedIn, จดหมายข่าว, สคริปต์วิดีโอสั้น** — ใช้ **Drafts for other channels** แต่ละร่างสร้างจากฉบับ **ที่อนุมัติแล้วเท่านั้น** โดยโมเดลเดียวกัน พร้อมคำสั่งห้ามเพิ่มข้อเท็จจริงใหม่ ร่างเหล่านี้ **ยังไม่ได้ทดสอบกับแพลตฟอร์มจริง** อ่านทุกร่างก่อนใช้ ร่างถูกเก็บที่ `data/exports/` ด้วย
5. เมื่อโพสต์แล้ว กด **📌 Record as posted** เป็นเพียงบันทึก (สำหรับแดชบอร์ด) ถ้าการตรวจข้อเท็จจริงยังมีรายการที่จับคู่ไม่ได้ ระบบจะขอให้ยืนยันว่าคุณตรวจเองแล้ว

## 12. ให้ Claude ตรวจครั้งสุดท้าย (MCP)

ให้ Claude (Desktop หรือ Code) **ตรวจครั้งสุดท้าย** ของบทความที่อนุมัติแล้วได้: เทียบตัวเลข ชื่อ คำพูดกับแหล่ง เกลาภาษา เตรียมฉบับ Blockdit (ไม่มี `[n]`)
และฉบับเว็บ (มี `[n]`) พร้อม **รายงานการปรับแก้** ที่บอกว่าเปลี่ยนอะไรและทำไม คุณจึงตรวจ *รายการที่เปลี่ยน* ไม่ต้องอ่านทั้งบทความซ้ำ

MCP server มี **เครื่องมือห้าตัว** และไม่มีทางเผยแพร่ อนุมัติ แก้สถานะงาน หรืออ่าน `.env` วิธีติดตั้งและกติกา: **[docs/MCP.md](MCP.md)** (ภาษาอังกฤษ)

สรุปสั้นๆ:
- **Claude Code:** `claude mcp add oba -- node /path/ที่แท้จริง/src/mcp-server.mjs`
- **Claude Desktop:** เพิ่มใน `claude_desktop_config.json` (Settings → Developer → Edit Config) ใช้ **path เต็ม** ของ `node` และของ `src/mcp-server.mjs` แล้วปิด Claude Desktop ให้สนิท (จากถาดระบบ) ก่อนเปิดใหม่
- สั่งงานเช่น: *"ตรวจครั้งสุดท้ายงาน OBA-xxxxxxxx เพื่อลง Blockdit และเว็บ"* แล้วเปิด `data/jobs/<id>/final/r<N>/change_report.md` ดูรายการแก้

## 13. ทำให้เป็นของคุณ: กติกา เทมเพลต น้ำเสียง

โฟลเดอร์ `rules/` เก็บกติกา **ตัวอย่าง** ระบบอ่านใหม่ทุกงาน — แก้ไฟล์แล้วงานถัดไปทำตามเลย ไม่ต้องรีสตาร์ต

| ไฟล์ | มีอะไร |
|---|---|
| `rules/AUTOMATION_RULES.md` | กติกากลาง: เป้าหมาย ลำดับ มาตรฐานหลักฐาน แนวเทมเพลต การตรวจและส่งมอบ Human Gate |
| `rules/OntheBridge_Voice_Library_v1.0.md` | หลักการน้ำเสียง **คำที่ควรหลีกเลี่ยง** (บรรทัดเดียวคั่นด้วยจุลภาค ที่โค้ดใช้สแกน) ตัวอย่างน้ำเสียง |
| `rules/BLOCKDIT_FORMAT.md` | รูปแบบช่องทางบทความยาว: หัวข้อ จำนวนคำ ภาพและแหล่งข้อมูล |
| `rules/Template/blockdit_article.md` | เลย์เอาต์ที่ AI ต้องทำตามสำหรับช่องทางนั้น |
| `rules/Template/*.yaml` | เทมเพลตทั้งห้า: ขั้น วัตถุประสงค์ คำถามนำ คำแนะนำความยาว |

ข้อบังคับเมื่อแก้ไฟล์ — ดูรายละเอียดใน [docs/RULES.md](RULES.md): หัวข้อ `## ...` ถูกค้น **ตามชื่อ** · บรรทัดคำที่ควรหลีกเลี่ยงถูกโค้ดอ่าน ·
ค่า `name:` ของแต่ละขั้นใน YAML ต้องตรงกับแผนที่ช่องใน `src/rules.mjs`

<a id="s13b"></a>
### เขียนบทความภาษาไทย

ไฟล์ใน `rules/` ที่ให้มาเป็นภาษาอังกฤษ ถ้าคุณเขียนบทความไทย **ควรเขียนกติกาของคุณเองเป็นภาษาไทย** โมเดลทำตามภาษาของกติกา และคุณเลือกภาษาของบทความต่องานในหน้าเว็บ (Article language = Thai) วิธีทำ:

1. **คัดลอกโฟลเดอร์ `rules/` เก็บไว้** ก่อนแก้ เพื่อกลับไปดูตัวอย่างได้
2. **คงหัวข้อ `## ...` เป็นภาษาอังกฤษ** (เช่น `## Goal`, `## Evidence`) เพราะโค้ดค้นตามชื่อ แต่เขียน **เนื้อหาใต้หัวข้อเป็นไทย** ได้ทั้งหมด
3. **บรรทัดคำที่ควรหลีกเลี่ยง** ใต้ `## Words to avoid in the narrator's voice` ให้เป็นบรรทัดแรกที่ไม่ว่าง คั่นด้วยจุลภาค (`,`) เช่น `ช็อก, เปิดโปง, ต้องอ่าน, ห้ามพลาด` ระบบสแกนทุกบทความและรายงานเป็น *ข้อสังเกต* (ไม่บล็อก เพราะคำพูดตรงของแหล่งอาจมีคำเหล่านี้)
4. **YAML ของเทมเพลต:** คงค่า `name:` ของแต่ละขั้นเป็นภาษาอังกฤษตามเดิม (ต้องตรงกับ `SLOT_MAP`) แต่เขียน `purpose`, `guiding_questions`, `length_hint` เป็นไทยได้
5. **ความยาว:** ภาษาไทยตั้งเป้า 1,500–2,200 คำ (นับด้วย `Intl.Segmenter` ซึ่งตัดคำไทยด้วยพจนานุกรม ผลอาจต่างจากโปรแกรมนับคำอื่น) แก้ได้ที่ `src/language.mjs` ถ้าแก้ ให้เขียนช่วงเดียวกันในกติกาด้วย
6. **ข้อสังเกตเฉพาะภาษาไทย:** ระบบเข้าใจปี พ.ศ. กับ ค.ศ. เมื่อตรวจตัวเลข (เช่น 2569 ↔ 2026) อ่านเลขไทย ๐–๙ ได้ และตรวจประโยคเปิดที่สมมติผู้อ่านแบบไทย ("คุณเพิ่ง…", "ลองจินตนาการ…", "สมมติว่า…") ส่วนการตัดข้อความสำหรับ Reels ภาษาไทย **ยังไม่รวมในรุ่นนี้**
7. **ทดสอบหลังแก้:** รัน `npm test` (ตรวจว่าหัวข้อหลักยังถูกค้นเจอ) แล้วลองงานหนึ่งเรื่องและอ่านผลเอง

## 14. โมเดล ภาษา และค่าใช้จ่าย

**ผู้ให้บริการและโมเดล** (เมนูในหน้าเว็บ)

| ผู้ให้บริการ | โมเดล | หมายเหตุ |
|---|---|---|
| DeepSeek | `deepseek-flash` (ค่าเริ่มต้น), `deepseek-v4-pro` | ผ่านการใช้งานมากที่สุด OBA **ปิด** โหมด "คิด" (thinking) ของโมเดลเหล่านี้ เพราะถ้าเปิด โมเดลอาจใช้งบคำตอบหมดกับการคิดแล้วไม่ตอบอะไร |
| Anthropic | Sonnet 5.5, Haiku 5.5, Haiku 4.5, Opus 5.5 | OBA ตั้งพารามิเตอร์โหมดคิดให้ถูกต้องตามแต่ละรุ่น ในการทดสอบของเรา Haiku เขียนจบงานแต่ **ต่ำกว่ามาตรฐาน** ของโมเดลใหญ่ |
| OpenAI, Gemini, OpenRouter | อยู่ในเมนู | ใช้ได้ แต่ **ยังไม่เคยรันทั้งงาน** |

**ควรใช้โมเดลไหน?** คุณภาพการเขียนขึ้นกับโมเดล ด่านตรวจไม่เปลี่ยน แต่โมเดลที่อ่อนกว่าเขียนบทความอ่อนกว่าและต้องแก้หลายรอบ
เราทดสอบ **DeepSeek** (Flash: ผ่านมาตรฐานทั้งงาน — ฐานที่ตรวจสอบแล้วและไม่แพง) และ **Claude** (Haiku 4.5/5.5: จบงานแต่ต่ำกว่ามาตรฐาน;
Sonnet 5.5 และ Opus 5.5: ต่อใช้งานได้แล้ว แต่ **ยังไม่เคยรันทั้งงาน**) ถ้าค่าใช้จ่ายไม่ใช่ปัญหา แนะนำลอง Claude รุ่นใหญ่ (Sonnet หรือ Opus)
เพราะโมเดลใหญ่โดยทั่วไปเขียนดีกว่า — เป็นความคาดหวัง ไม่ใช่สิ่งที่เราวัดได้ ถ้าจะตัดสินเอง รันหัวข้อเดียวกันกับสองโมเดลแล้วเทียบจำนวนรอบแก้และข้อเท็จจริงที่ผ่าน

**ภาษา** — ตั้งต่องาน อังกฤษเป้า 1,200–1,800 คำ ไทย 1,500–2,200 คำ แก้ช่วงได้ที่โปรไฟล์ใน `src/language.mjs` (และให้ `rules/BLOCKDIT_FORMAT.md` สอดคล้องกัน)

**ค่าใช้จ่าย** — หนึ่งงานเรียกโมเดลราว 12–30 ครั้ง (หลายครั้งใหญ่: ขั้น evidence ส่งข้อความของหน้าเว็บทั้งหน้า) แท็บ **Insights** แสดงยอดประมาณการ
รายเดือนและรายผู้ให้บริการจากตารางอัตราใน `src/skills/costTracker.mjs` **ตารางเหล่านั้นเป็นค่าประมาณ ให้ตรวจหน้าราคาของผู้ให้บริการแล้วแก้ตัวเลข**
หน้าบิลของผู้ให้บริการคือความจริง ตัวเลขเป็นสกุล USD

## 17. คำถามที่พบบ่อย

**ระบบเผยแพร่แทนฉันไหม?** ไม่ และทำไม่ได้: ไม่มีตัวเผยแพร่และไม่มี credential ของแพลตฟอร์มในระบบเลย

**บทความ "ตรวจข้อเท็จจริงแล้ว" ไหม?** *ตรวจ* — ข้อเท็จจริงผูกกับแหล่งที่เปิดอ่านจริง และคำอ้างอิงถูกตรวจด้วยโค้ด แต่นั่นไม่ใช่การตรวจโดยผู้เชี่ยวชาญอิสระ ต้องอ่านเอง นั่นคือจุดประสงค์ของด่าน

**ใช้กติกาบรรณาธิการของฉันเองได้ไหม?** ได้ — นั่นคือวิธีใช้ที่ตั้งใจไว้ ดู[หัวข้อ 13](#s13)

**เขียนภาษาอื่นได้ไหม?** ตัวระบบไม่ผูกกับภาษา มีโปรไฟล์ให้สองภาษา (อังกฤษ ไทย) ดู `src/language.mjs`

**ทำไมบางงานหยุดที่ "needs revision"?** หลังแก้ภายในสามรอบ ยังมีข้อที่ต้องแก้ ระบบแสดงรายการให้ คุณสั่งแก้ ยอมรับ หรือยกเลิกได้

**หลายคนใช้พร้อมกันได้ไหม?** เป็นเครื่องมือในเครื่องสำหรับผู้ใช้คนเดียว ไม่มีล็อกอิน บรรณาธิการหลายคนใช้เครื่องเดียวกันและใส่ชื่อที่ด่านได้ แต่ใครเปิดหน้าได้ก็ตัดสินได้

**พบปัญหาความปลอดภัยแจ้งที่ไหน?** ดู [SECURITY.md](../SECURITY.md) — กรุณาอย่าเปิด issue สาธารณะสำหรับช่องโหว่

## 19. ภาคผนวก ก: การทดสอบจริงที่ผลไม่ดี และสิ่งที่เรียนรู้

เราเก็บเรื่องนี้ไว้ในคู่มือโดยตั้งใจ เพราะแสดงว่า OBA ทำอะไรเมื่อได้ข้อมูลน้อยเกินไป และคุณควรมองหาอะไร

**การตั้งค่า** หัวข้อ: *"IMF World Bank annual meeting in Bangkok 2026"* ภาษาอังกฤษ DeepSeek Flash **ไม่มี key ค้นเว็บ** เทมเพลตและ pillar ให้ AI เลือก (ตุลาคม 2026)

**เกิดอะไรขึ้น** — 66 วินาที เรียกโมเดลเก้าครั้ง ราว 126,000 โทเคน ค่าใช้จ่ายประมาณ **$0.05** ครบทั้งแปดขั้นและงานหยุดที่ *ready for human review*

**ระบบทำถูกอะไร**

- ทุกวันที่ สถานที่ และคำอ้างอิงในบทความตรงกับหน้าเดียวที่ใช้ (เราตรวจทุกข้อกับข้อความแหล่งที่บันทึกไว้)
- เตือนฐานที่อ่อนบนการ์ด: *"Thin evidence base: from only 1 source organisation(s) … 100% of the facts come from one organisation, wikipedia.org"* และ *"the source relevance filter was relaxed because fewer than 2 sources remained"*
- ไม่แต่งตัวเลขหรือชื่อ และไม่อนุมัติหรือเผยแพร่อะไร

**อะไรผิด และเรียนรู้อะไรจากแต่ละข้อ**

| สิ่งที่พบ | ทำไมเกิด | ควรทำอย่างไร |
